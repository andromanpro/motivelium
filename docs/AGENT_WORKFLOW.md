# Создание видео с ИИ: состояние alpha.3 и следующий этап

21 октября 2026. Главный замысел Motivelium: ИИ собирает редактируемое видео по обсуждённому замыслу, человек смотрит результат и доводит детали. Ручная студия обеспечивает эту доводку, просмотр и контроль результата.

## Рабочее дополнение MCP после alpha.3

Реализован локальный stdio MCP: 21 инструмент для каталога, создания проектов, импорта, черновиков, реальных PNG/короткого прохода, доработки, применения/Undo и экспорта. [Подключение и ограничения](MCP.md). На новом демо проверены внешний агент, две визуальные доработки, применение/Undo/Redo, ручная правка через студию, MP4 со звуком и ZIP. Опубликованный установщик alpha.3 не заменялся.

## Что реализовано в опубликованной alpha.3

| Часть | Состояние alpha.3 |
| --- | --- |
| Документ и операции проекта | Сцены, узлы, эффекты, ключи, камера, аудио и ресурсы; пакеты проверяются целиком, есть ревизии и Undo/Redo |
| Локальный HTTP API | Создание проекта/копии/проекта из шаблона, чтение графа, транзакции, ресурсы, история, MP4 и ZIP |
| Создание проектов внешним ИИ | Работает через код сборки и JSON проекта; этот путь использован для редактируемых демо Motivelium |
| Встроенные ИИ-правки | GLM меняет выбранный объект и его эффекты; видит переданные кадры до/после, проверяет примерку; результат применяет пользователь |
| Ограничение повторов | До двух доработок, шести модельных вызовов и шести минут; остановка при повторе результата/замечаний, отсутствии улучшения и других причинах |
| Ручная доводка | Холст, слои, параметры, ключи, галереи и история изменений |
| MCP-сервер | **Не реализован** |
| Целый ролик из описания во встроенном ИИ | **Не реализован**; текущая ИИ-правка ограничена одним выбранным объектом |

Проверенные основания: [HTTP API](../server/api.ts), [операции проекта](../studio/domain/operations.ts), [ограничения ИИ-правки](../studio/agent/proposal.ts), [ограничения самопроверки](../studio/agent/auto.ts). В текущей встроенной самопроверке кадры снимает интерфейс и передаёт серверу. Отдельного универсального API «отрисуй кадры этого черновика» пока нет.

## Как сейчас создаются демонстрационные ролики

Внешний ИИ пишет код, который собирает обычный документ Motivelium: сцены, объекты, эффекты, ключи, камеры и аудио. Так устроены [«Обзор возможностей»](../studio/domain/showcase.ts), [«Разряд»](../studio/domain/energy.ts) и [«Материя»](../studio/domain/matter.ts). [Сборщик стартовых шаблонов](../tools/build-template-projects.mjs) также формирует и проверяет обычные проекты. Набор «Механика — три сборки» импортируется и экспортируется студией как редактируемый проект с моделями и музыкой.

Полученный документ открывается в студии, использует её рендерер и эффекты и допускает ручную доводку. Создание проекта внешним ИИ уже работает; для него сейчас нужны код и знание схемы. Встроенный ИИ-диалог пока решает более узкую задачу — правку выбранного объекта.

MCP должен предоставить внешний доступ к уже существующим механизмам создания, изменения, просмотра и экспорта. Он уменьшит количество специального кода и ручной подготовки контекста для каждой новой сессии. Это следующий способ подключения, а не условие, без которого ИИ вообще не может создавать ролики в Motivelium.

## Замысел MCP, реализованный в рабочем дополнении

Ниже исходный замысел подключения. Реальные имена инструментов, настройки и границы текущего выполнения описаны в [MCP.md](MCP.md).

1. **Возможности и каталог.** Агент получает поддерживаемые типы объектов/операций и находит подходящие эффекты, шаблоны и композиции. Каталог возвращает схемы параметров и совместимость, без необходимости читать весь исходный код или тысячи карточек.
2. **Создание проекта.** Пустой документ или шаблон; добавление сцен, объектов, ресурсов, ключей, камер и аудио через те же операции, которые использует студия.
3. **Примерка целого изменения.** Пакет операций проверяется на отдельном черновике с привязкой к исходной ревизии. Основной проект не меняется до применения; не следует расширять старый валидатор одной ИИ-правки до произвольных полномочий.
4. **Зрение и движение.** Агент запрашивает кадры/контактный лист и короткий проход для оценки переходов и анимации. Один хороший стоп-кадр не считается проверкой движения. Рендер черновика должен работать без ручной съёмки кадра в открытом редакторе.
5. **Доработка и контроль.** Несколько ограниченных проходов по замечаниям, остановка при исчерпании лимита или отсутствии улучшения; затем пользователь смотрит результат, применяет или отклоняет. Ручная правка и Undo используют прежнюю историю.
6. **Финальный рендер.** MP4 из конкретной ревизии, статус и отмена задания; ZIP для сохранения редактируемого результата.

Модель выбирает подключённый внешний агент. Встроенная GLM-панель остаётся отдельным способом локальной правки объекта; её ключ и подписка не должны становиться обязательными для работы другого агента с MCP.

## Критерий готовности этапа

Внешний агент через реальное MCP-подключение создаёт новый короткий ролик из пустого проекта: несколько сцен, текст/изображение, разные эффекты, движение камеры и музыка. Он получает реальные превью и короткий проход, исправляет результат с ограничением числа попыток; человек делает ручную правку и отменяет её; после перезапуска проект сохраняется, MP4 содержит нужное изображение и звук, ZIP переносится.

Нужна проверка как минимум двумя внешними клиентами/моделями. Реальные платные/подписочные прогоны запускаются по отдельному поручению. Первый MCP-проход выполнен внешним агентом Codex и проверен SDK-клиентом и соединением протокола 2025 года. Другие реальные модельные клиенты отдельно ещё не прогонялись.
