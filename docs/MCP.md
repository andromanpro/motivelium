# Motivelium MCP

MCP входит в Windows-выпуск0.2.0-beta.1 и в исходники. Уже опубликованный установщик `v0.1.0-alpha.3` остаётся прежним и MCP не содержит. MCP подключается к работающей студии через локальный API. В Windows-кандидате откройте **Настройки → ИИ** и скопируйте готовую конфигурацию: включённый Node подходит для запуска MCP, отдельная установка Node не требуется. Для запуска из исходников сначала выполните `node tools/setup.mjs`; нужен Node 24.12+ в ветке 24.x.

## Подключение

Запустите студию, затем добавьте MCP-сервер в клиент с поддержкой **stdio**. Пример распространённого формата конфигурации (пути замените на свои):

```json
{
  "mcpServers": {
    "motivelium": {
      "command": "C:/Program Files/nodejs/node.exe",
      "args": [
        "D:/Projects/Motivelium/mcp/server.mjs",
        "--url", "http://127.0.0.1:8676",
        "--state-dir", "D:/Projects/Motivelium/.local/mcp",
        "--asset-root", "D:/VideoMaterials"
      ]
    }
  }
}
```

Точное имя раздела/файла настроек зависит от вашего клиента. Укажите абсолютный путь к Node и `server.mjs`; текущая папка клиента несущественна. Проверка справки: `node mcp/server.mjs --help`. `npm run mcp` запускает тот же процесс, но для клиента предпочтительнее прямой запуск Node, без вывода npm в канал протокола.

`--url` допускает только HTTP на loopback. Сервер студии должен быть уже запущен; MCP не закрывает и не перезапускает его. Порт установленного приложения может отличаться. Если `--state-dir` не задан, используются `MOTIVELIUM_DATA_DIR/mcp` или `.local/mcp` этой копии. `--asset-root` необязателен и нужен только для импорта файлов. Файлы за пределами указанной папки и ссылки наружу отклоняются.

Сам MCP не вызывает модель, не читает профили Hermes/DSH и не требует ключей GLM. Модель и оплату выбирает внешний клиент. Встроенная GLM-панель продолжает работать отдельно.

## Компактное чтение (MCP.3)

По умолчанию `create_project`, `get_project`, `get_draft`, импорт, применение и Undo/Redo возвращают краткую квитанцию. В `project` остаются ID, ревизия, размер, FPS, длительность и счётчики; массивов `nodes/effects` там нет. Это позволяет продолжать работу по ревизии без повторной загрузки всего графа после каждой операции. Импорт сохраняет сведения о добавленном ресурсе.

Три инструмента дают нужную часть документа:

- `project_overview` — краткий обзор сцен, ресурсов и дорожек, с точными общими количествами. Для длинного списка есть `section:"scenes"|"assets"|"tracks"|"cues"`, `offset` и `limit`.
- `list_nodes` — объекты по `sequenceId`, `parentId`, `kind`, `ids`, словам имени или текста. `detail:"properties"` возвращает свойства без длинных массивов анимации. `detail:"keys"` и один ID в `ids` дают страницу ключей этого объекта. `parentId:null` означает только корневые объекты; отсутствие фильтра включает вложенные.
- `list_effects` — экземпляры эффектов с точными ID и параметрами: по `targetId`, `sequenceId`, `definitionId`, `ids`, `enabled` и словам. `includeDescendants:true` включает эффекты детей выбранной группы.

Пример поиска и исправления подписи готовой композиции:

```json
{"projectId":"PROJECT_ID","sequenceId":"scene-final","kind":"text","query":"MOTIVELIUM","limit":8}
```

Передайте это в `list_nodes`, затем используйте возвращённый ID в `updateNode`. Для эффектов этой надписи вызовите `list_effects` с её `targetId`. Не нужно получать весь проект или угадывать сгенерированные ID. Те же запросы принимают неприменённый `draftId` вместо `projectId`.

Страница содержит `total`, `returned`, `nextOffset` и ревизию. Следуйте `nextOffset`, пока он не станет `null`. `expectedRevision` закрепляет чтение живого проекта: при ручной правке между страницами сервер вернёт409 и предложит начать выборку заново. Черновик неизменяемый и сообщает `draftId/baseRevision`. Все заданные фильтры соединяются AND, слова запроса также обязательны.

Компактная страница ограничена **8 000 байт UTF-8**, поэтому может вернуть меньше указанного `limit` (до30 элементов). Длинные текстовые поля и вложенные данные помечаются `textTruncated`/`truncatedFields`; их нельзя отправлять назад как полную замену свойства. Массивы ключей читаются отдельными страницами. Полный документ для редкой диагностики доступен явно: `get_project({projectId,response:"full"})`. Для прежнего клиента можно запустить сервер с `--response-mode full`; это сохраняет старые полные квитанции. Формат хранимого проекта и история студии не менялись.

Справка также разделена: `capabilities` без параметров даёт короткий маршрут; `section:"nodes"|"operations"|"timing"|"reading"` раскрывает нужную часть. В `operations` есть `offset/limit`. Старый полный контракт доступен через `section:"full"` и может быть большим. Это важно для клиентов, которые сами усекают длинные ответы. Страницы каталога эффектов/шейдеров ограничены примерно6КБ; следуйте `nextOffset`, даже если сервер вернул меньше запрошенного количества.

## Рецепты времени и проба переходов (MCP.2)

`capabilities(section:"timing")` возвращает `timingRecipes`, а разделы `nodes` и `operations` — готовые образцы узлов и операций: появление/уход, локальные координаты группы, камеры, аудио, метки и соседние сцены. В полном режиме эти данные по-прежнему находятся в `document`. Исходники для обычного ролика читать не требуется.

Эффект действует только внутри `[fromFrame,toFrame)`. До и после этого интервала объект имеет базовое состояние. Ключи, напротив, сохраняют первый/последний transform. Для сцены `[0,180)` последний кадр — **179**, а исключённый конец — **180**. Чтобы погасший объект не вернулся на последнем кадре, используйте ключ opacity=0 с удержанием до конца.

`propose_timing` готовит такой черновик для списка до 24 статичных слоёв:

```json
{"draftId":"DRAFT_ID","items":[{"nodeId":"title","showAtFrame":30,"fadeInFrames":15,"hideAtFrame":120,"fadeOutFrames":15}]}
```

Он скрывает слой до f30, проявляет до f45, держит видимым до f105 и гасит к f120. Невидимость сохраняется до f179. `hideAtFrame:"scene-end"` означает последний кадр сцены. Можно передать живой `projectId` и `expectedRevision` вместо `draftId`. Чужие ключи и эффекты появления инструмент не перезаписывает: для уже анимированного слоя нужно сознательно объединить анимацию обычными операциями. Все созданные ключи редактируются в студии и отменяются вместе с применением черновика.

`preview_transition({shaderId:"gl-circleopen",width:640})` возвращает шесть настоящих PNG (включая середину) и трёхсекундный MP4 перехода между синей сценой A и янтарной B. Рабочий проект не меняется. Можно передать `params` из каталога. CircleCrop, например, может уходить в цвет подложки, а DreamyZoom даёт светлую вспышку — это видно в пробе. Точная повторная проба берётся из проверенного кэша.

## Общий бюджет поручения

По умолчанию: **6 вариантов, 8 рендеров превью и 20 минут** от первого варианта/рендера. Один счётчик относится ко всем проектам, propose/refine и перезапускам MCP в одном `run-key`. Рендеры переходов тоже учитываются. Неверная попытка подготовить вариант расходует итерацию; точный повтор той же попытки не расходует ещё одну. Повтор успешного превью использует кэш; неудачная новая отрисовка расходует попытку.

Ответы содержат `budget`; отдельный `run_status` показывает ограничения и остаток. Потолки вариантов и рендеров независимы: шестой вариант можно ещё посмотреть, если остались превью и время; девятый новый рендер запрещён. Истечение общего срока запрещает оба вида новой работы. Чтение, применение уже готового черновика, Undo/Redo и экспорт доступны, чтобы сохранить лучший результат. Лимит трёх `refine_draft` одной цепочки сохраняется дополнительно.

Ключ поручения и потолки задаёт запускающая сторона, вне инструментов модели:

```text
--run-key lamp-repeat-20261022 --max-iterations 6 --max-previews 8 --max-seconds 1200
```

Журнал хранится в `state-dir/runs/`; перезапуск не меняет его потолки. Модель не может повысить лимит или начать новый бюджет MCP-вызовом. Для нового явно порученного запуска оператор выбирает новый `run-key`. Смена каталога состояния или ключа вне MCP является новым контекстом оператора; это ограничение работы агента, а не защита от владельца компьютера с доступом к файлам. Ручное редактирование в студии бюджетом не ограничено.

Этот бюджет считает операции Motivelium. Вызовы самой LLM и её внешних визуальных рецензентов MCP не видит: общий срок работы и число обращений к другим моделям задаёт запускающий клиент. В тестовом DSH-проходе дополнительно задан тайм-аут1200секунд; не более двух визуальных рецензий — инструкция модели, а не серверная гарантия. Ошибки входной схемы, отвергнутые SDK до вызова bridge, не создают вариант и не расходуют итерацию.

## Рабочий путь агента

1. `capabilities` — получить формат, операции, примеры и правила; `catalog` — найти эффекты/шейдеры/композиции/шаблоны со схемами параметров.
2. `create_project` — создать пустой проект или копию шаблона. `import_media`/`import_model` — при необходимости перенести собственные ресурсы; их добавление — отдельная отменяемая операция.
3. `propose_changes` — проверить пакет операций на копии. `propose_composition` — вместо ручной сборки примерить готовую комбинацию камеры, типографики, света и частиц. Оба возвращают `draftId`, не меняя живой граф.
4. `render_preview` — получить до шести настоящих PNG от общего рендерера. По умолчанию включены последние два кадра; границы остальных сцен задайте явно. `render_clip` — получить короткий проход до четырёх секунд; он **без звука**, предназначен для проверки движения. Возвращаются до шести выбранных кадров, короткий клип с SHA и путь полного manifest, без громоздкого списка всех PNG. PNG render_preview/preview_transition также возвращаются как MCP image content.
5. `refine_draft` — добавить изменения по увиденному. Создаётся новый неизменяемый черновик; допускаются три доработки в цепочке. Остановиться раньше, если улучшений нет. Нельзя считать пару стоп-кадров проверкой всего движения.
6. `apply_draft` — применить результат одной транзакцией. Повтор того же `draftId` идемпотентен. При ручном изменении исходной ревизии — конфликт, без перезаписи.
7. Ручная доводка на холсте и в свойствах использует те же объекты и общую историю. `undo`/`redo` работают с этой историей; `get_project`/`history` показывают текущее состояние.
8. `export_video` → `export_status` — полный MP4 со всеми активными звуковыми дорожками; `cancel_export` отменяет задание. `export_project` сохраняет переносимый ZIP.

Сначала обсудите замысел и ключевые кадры. Для запросов создания/импорта/экспорта используйте стабильный `requestId`; после неизвестного исхода повторяйте его с теми же параметрами. Новый ID может создать ещё один проект или задание. Для изменения операций нужна актуальная `expectedRevision`. Один пакет — до 200 операций.

Для первого прохода выгоднее шаблон/готовая композиция или несколько небольших пакетов примерно по20–40операций. Долгая генерация одного гигантского JSON может занять больше времени, чем весь просмотр и экспорт; MCP не ускоряет саму генерацию токенов. Оставляйте одну-две итерации бюджета на исправления. В `catalog` все слова запроса обязательны: альтернативы ищите отдельными короткими запросами.

Переход принадлежит **входящей** сцене, у которой есть соседняя предыдущая. Первая сцена не имеет входящего перехода. Все времена — номера кадров, конец интервала исключён. Параметры и совместимые типы объектов берите из каталога, а не угадывайте.

## Раскадровка

В рабочей версии есть `capabilities(section:"storyboard")` с готовыми примерами операций. `list_storyboard` возвращает компактные страницы карточек с их ID, состоянием, длительностью, изображением и связью со сценами. `get_story_card` читает одну карточку; отдельное поле — через `field`, длинный текст — по `nextTextOffset`, замечания — страницами `field:"comments"`. Общий замысел доступен через `field:"synopsis"` без cardId.

`preview_story_card` показывает сохранённое изображение или реальный кадр сцены (`view:"montage"`). `propose_story_capture` снимает кадр связанной сцены и готовит его на примерку; проект меняется только после `apply_draft`. Варианты и рендеры расходуют тот же общий бюджет. Для внешнего эскиза: `import_media`, затем `updateStoryCard` с изображением `{assetId,origin:"concept"}`.

План меняется через обычный `propose_changes`: `setStorySynopsis`, `upsertStoryCard`/`updateStoryCard`, `reorderStoryCard`, `removeStoryCard`, `addStoryComment`/`updateStoryComment`/`removeStoryComment`. Все изменения отменяются общей историей. Карточки и картинки включаются в ZIP. Перестановка карточек не переставляет монтажные сцены автоматически. Полное описание — [STORYBOARD.md](STORYBOARD.md).

## Примерка и сохранность

Черновики и изображения сохраняются в `--state-dir`; после перезапуска MCP их можно читать. При современном `/api/health` они связаны с адресом и папкой данных студии. Для старого сервера без `dataRoot` дополнительно учитывается PID: после его перезапуска нужно подготовить новый черновик. Токен API используется только внутри процесса и не включается в ответы MCP.

Ресурсы примерки сверяются по SHA/размеру, а затем обслуживаются из памяти снимка. Превью использует штатные `evaluateFrame/renderFrame/createThreeAdapter`, как экспорт. Внешние сетевые ресурсы рендерер не загружает. На примерку действует 90-секундный предел; поддерживается отмена через сигнал клиента. Параллельные примерки отклоняются, чтобы не плодить GPU-контексты.

Запись о применении в `get_draft.application` — историческая квитанция. После Undo она не означает, что изменения по-прежнему находятся в текущем проекте: смотрите актуальный граф и историю. Удаления проекта через MCP нет; Undo возвращает состояние редактирования, а созданный пустой проект остаётся в списке.

Для PNG-превью нужен Chrome и собственный playwright-core. Для короткого прохода дополнительно нужен FFmpeg с H.264; полный экспорт и импорт проверяют свои внешние зависимости, как обычная студия. Нельзя обещать одинаковые пиксели на разных GPU.

Это рабочее подключение инструментов к внешнему агенту. Оно не добавляет в окно студии отдельный диалог автоматического создания всего ролика. Внешний агент проводит творческий цикл, выбирает инструменты и оценивает изображения; результат остаётся редактируемым в студии.


## Звук и музыкальный монтаж

Рабочая версия от 27.10.2026: `capabilities(section:"audio")` описывает короткий маршрут. `sound_catalog` даёт страницы звуков с источником, лицензией, длиной, пиком и рекомендуемой громкостью. `propose_sound` помещает начало, пик или конец выбранного звука на кадр; ресурс пока в staging, граф проекта прежний до `apply_draft`.

`analyze_audio` анализирует выбранный фрагмент аудиофайла локально: темп, первую найденную долю, выраженность ритма и предупреждения. Ответ без PCM и длинной волны. Это предложение: возможен половинный/двойной темп; первая доля такта и музыкальные фразы требуют слуховой проверки. `propose_music_grid` принимает явные `bpm`, `firstSeconds` и `every:1|2|4|8|16`. Не более 160 меток. При `replace:true` меняется только созданная программой сетка этой дорожки; авторские фразы и акценты сохраняются.

Обрезка, затухание, панорама и приглушение музыки задаются `updateAudioTrack` через обычный `propose_changes`:

```json
{"op":"updateAudioTrack","targetId":"sound-track","values":{"name":"Щелчок по кнопке","gain":0.35,"offsetSeconds":6,"clip":{"sourceStartSeconds":0,"durationSeconds":0.4,"fadeInSeconds":0.005,"fadeOutSeconds":0.03,"pan":0,"duckMusicDb":3}}}
```

`offsetSeconds` — начало на таймлайне; `sourceStartSeconds` — начало внутри файла. `durationSeconds` — длина клипа. Панорама от −1 до 1; `duckMusicDb` от 0 до 24 дБ действует на музыку во время немузыкальной дорожки. Один Apply создаёт одну отменяемую транзакцию; параметры и лицензия остаются в ZIP. Прослушивание — в студии, «Звук и ритм», или `panel=audio`. `render_clip` по-прежнему без звука: его нельзя считать проверкой сведения.
