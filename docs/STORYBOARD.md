# Раскадровка проекта

24.10.2026. Архитектура первой реализации по поручению пользователя.

Дополнение26.10, alpha.4: добавлены примерка сборки сцен по выбранным карточкам, обычные редактируемые узлы/ключи/камера, применение одной транзакцией и MCP assemble_storyboard. Само перемещение карточки по-прежнему не меняет монтаж. ZIP с раскадровкой теперь имеет формат2 и явные требования читателя; alpha.3 не обновлялась.

Раскадровка — необязательное поле `storyboard` документа Project v2. Старые проекты без него продолжают открываться без перезаписи. Вложенная структура имеет свою версию 1. Установщик alpha.3 не обновляется; старый редактор с его строгой схемой не сможет открыть документ с новой раскадровкой.

Внутри: общий замысел и упорядоченные карточки со стабильными ID. У карточки — заголовок, описание, предполагаемая длительность, камера, переход, звук, источники, состояние выбора и замечания. Карточка может существовать до монтажа. Связь со сценой и объектами необязательна; удаление сцены не стирает обсуждение, а показывает нарушенную связь.

Ключевой кадр ссылается на обычный ресурс изображения проекта. Эскизы можно импортировать, снимок монтажа — сохранить общим рендерером. Изображения включаются в существующий ZIP, без абсолютных путей и отдельного внешнего хранилища. Удаление используемого изображения блокируется. Снимок хранит номер кадра и отпечаток структуры своей сцены; метаданные раскадровки в отпечаток не входят. Это индикатор изменений монтажа, а не проверка попиксельного совпадения.

Все изменения проходят через обычные операции и транзакции: замысел, карточка, порядок, замечания. Поэтому общие Undo/Redo, ревизии, конфликты и перенос сохраняют раскадровку вместе с проектом. Черновик формы не применяется при внешнем изменении проекта; пользователь сверяет его с новой ревизией. Менять время сцены или собирать монтаж автоматически при перестановке карточек первая версия не должна.

MCP получает компактные страницы карточек и полный текст отдельного поля по запросу. Замечания читаются страницами. Отдельное превью показывает сохранённый эскиз или реальный кадр связанной сцены. Изменение плана — обычная примерка через propose/apply с тем же общим бюджетом, без скрытых вызовов моделей.

Проверка первой реализации: шесть карточек согласованного ролика Motivelium, изменение замысла и замечания, примерка через MCP, ручное редактирование, отмена и повтор, сигнал изменения сцены, импорт ZIP в пустое хранилище и совпадение изображений и ссылок. Само наличие статуса «Выбран» не означает художественной приёмки всего проекта.
